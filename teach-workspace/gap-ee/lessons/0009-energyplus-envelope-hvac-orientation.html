2. What just happened, physically

1ZoneUncontrolled.idf is a single thermal zone with no HVAC: EnergyPlus solved hourly heat balance — conduction through walls (lesson 0001), solar gains through windows, infiltration, internal gains — driven by a full TMYx meteorological year for Ho Chi Minh City. The .epw/.ddy/.stat trio from climate.onebuilding.org carries typical-year weather, ASHRAE design days (equipment sizing), and climate summaries. That machinery is world-class for one question class: buildings — envelope loads and HVAC systems serving them.

3. Why standby — the scope mismatch

  • The engagement's decarbonization targets are process end uses: dye baths, wash water, dryers fed by a steam boiler and a hot-water loop. Those are industrial thermal systems, not building zones.
  • EnergyPlus models process loads only as crude schedule-based "other equipment," with no steam headers, no boiler efficiency curves tied to load, no COP-vs-lift physics, no TOU tariff optimization. It cannot answer "what replaces coal steam at what size."
  • Its realistic future role: if a supplier's factory floor ventilation/cooling load turns out to be a material EE opportunity (fans, make-up air, envelope), EnergyPlus quantifies it — complementing MEASUR's pump/fan modules. Until that question firms up: shelf.

The transferable skill is the pattern, not the tool: localize weather/data first (it shipped US-only — like every tool in this stack), verify ingestion explicitly (the Site:Location grep), then ask whether the tool's model class matches the physical question at all.

Practice quiz

  1. What does the Site:Location line in eplusout.eio actually confirm?

    • That the IDF file parsed without errors
    • That EnergyPlus holds an official Vietnam license
    • That the HCMC weather file was genuinely ingested — name, lat/long, timezone, elevation all match Tan Son Nhat
    • That results will match a US-city simulation

    A wrong or missing -w argument can silently default to an internal location; the eio line is the positive proof the tropical year drove the simulation. Verify ingestion, never assume it.

  2. In out/eplusout.err, which lines signal a failed run by EnergyPlus convention?

    • **Severe** and **Fatal** lines — warnings alone are normal
    • Any Warning line at all
    • A nonzero file size
    • Mentions of EASIUR or AVERT

    This run: 3 warnings, 0 severe, 0 fatal = healthy. The warning/severe/fatal ladder is EnergyPlus's own severity convention — read the err file before quoting any number from an E+ run.

  3. Why do the outputs of this lesson create zero risk to ee-heat's tracked state?

    • Because EnergyPlus writes outputs to the Windows temp directory
    • tools/energyplus/ is entirely gitignored in ee-heat — untracked by construction, unlike the practice-copy rule used for REopt
    • Because we committed the outputs first
    • Because the IDF is read-only

    Two isolation patterns in this course: REopt practice work goes to a copy in agentic-degrees; EnergyPlus already sits inside an ignored tree of ee-heat. Both keep client history clean by different mechanisms.

  4. Why is EnergyPlus ranked standby for THIS engagement despite running perfectly?

    • It cannot simulate tropical climates accurately
    • It is proprietary and expensive to license
    • It models building envelopes and their HVAC — not dye-house steam systems; the engagement's targets are process end uses
    • It has no hourly resolution

    Model-class mismatch: no steam headers, no boiler part-load economics, no TOU optimization. A perfect answer to a question nobody asked is still the wrong tool — hence rank 4/5 and "do not spend Stage 1 hours here."

  5. Under what plausible future development does EnergyPlus re-enter scope?

    • If EVN raises electricity tariffs further
    • When R1234ze(Z) becomes unavailable
    • If factory-floor ventilation/cooling proves to be a material EE opportunity — envelope/HVAC modeling then complements MEASUR's fan/pump sweep
    • It never does — the tool is being removed from the toolchain

    Standby ≠ dead: the README names the exact trigger (ventilation/cooling as a material opportunity). Tool ranking is scoped judgment, not permanent verdicts.

  6. The localization problem EnergyPlus shared with every other tool in the stack:

    • It shipped US-only defaults — 5 US weather files — so VN/ID weather had to be added before any local run meant anything
    • It lacked a graphical interface
    • It could not run on Windows
    • It refused metric units

    MEASUR: US prices/factors. REopt: US tariffs/emissions lookups. heat_pump_model: Colorado site. EnergyPlus: US weather. The localization layer IS the engagement's core engineering contribution — remember it whenever a new tool arrives.

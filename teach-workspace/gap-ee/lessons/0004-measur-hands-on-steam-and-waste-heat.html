0004 · MEASUR Hands-On: Steam & Waste Heat

gap-ee week 1, days 3-4 · 90-120 min hands-on (GUI) · manual-entry checklist + concept quiz · mission

Time to drive the rank-1 tool. MEASUR v1.8.3 is a Windows GUI app with no CLI and no scriptable settings — it stores configuration in a local database inside the app — so this lesson is a hands-on walkthrough you complete by hand. You will localize MEASUR to Vietnam from the VN settings card, then run the Steam System Modeler and Waste Heat Recovery modules against the placeholder garment-plant defaults. Tick the checklist boxes yourself as you go.

Mission link. This is the "shrink the load" half of the tool-ordering rule. Whatever load survives this lesson's measures becomes REopt's ProcessHeatLoad in lesson 0006. The VN values you enter here (three tariff rates, coal price, emission factors) are the same numbers REopt reads from vn_context.json — two tools, one source of truth.

Before you start

  • MEASUR lives at %LOCALAPPDATA%\Programs\MEASUR\MEASUR.exe (v1.8.3).
  • The single source of truth for every value below is C:\Users\tukum\Downloads\ee-heat\tools\measur\VN-settings-card.md. If this lesson and the card ever disagree, the card wins — and if a fresh Windows profile runs this lesson, the settings must be re-entered from scratch; do not assume they persist.
  • Fuel-type note: the modeler's fuel list is built around US fuels. Pick the closest solid fuel for the coal-fired boiler and override price and emission factor to the card's values — the same workaround as REopt's. If the module will not accept that workaround cleanly, say so explicitly in your notes and point back at the card's "Fuel type" section rather than silently picking a different value.

Part A — Localization checklist (tick by hand)

  1. Units → Metric. Settings → Default Settings. Plant data arrives in tonnes steam/h, bar(g), °C, kJ (lesson 0001). ☐
  2. Electricity prices (excl. VAT): normal $0.06983/kWh, off-peak (00:00–06:00) $0.04533/kWh, peak (Mon–Sat 17:30–22:30) $0.12945/kWh. MEASUR takes one electricity price per assessment — use normal for a general sweep. ☐
  3. Boiler fuel: closest solid-fuel entry, overridden to $5.02/GJ (= $5.30/MMBtu). ☐
  4. Emission factors: grid electricity 0.1831 kg CO₂/MJ; coal 92.1 kg CO₂/GJ. Never leave the US grid factor — it understates Vietnam's by ~40% and overstates every electrification measure's abatement. ☐
  5. Sanity check: confirm $5.02/GJ × 1.055 ≈ $5.30/MMBtu matches the card. ☐

Part B — Steam System Modeler on garment-plant defaults

Build the placeholder plant from the card's table:

  • Steam header ≤ 10 bar(g)
  • Dye-house / HTHW loop 60–95°C, wash water 40–60°C, dryers/stenters 80–120°C
  • Boiler efficiency 75% as-found
  • Operating pattern 16 h/day, 5–6 days/week (two shifts)

Then, following lesson 0003's order: set condensate return rate, blowdown rate, flash recovery, excess air — and read what each change does to delivered-heat cost. Run any measure that shifts when energy is used (heat recovery with storage, off-peak charging) twice — once at off-peak ($0.04533/kWh), once at peak ($0.12945/kWh) — because the 2.86× spread changes which measure wins. Record your baseline vs. optimized steam-load numbers; that delta is exactly the load-reduction layer the engagement wants quantified. ☐

Part C — Waste Heat Recovery module

Point the module at the stack-gas and blowdown streams from Part B's baseline. Compare its recoverable-heat estimate against the savings the Steam System Modeler attributed to Checks 2–4. They should tell one coherent story — if they wildly disagree, re-check your entered settings before believing either. ☐

Practice quiz — what each module computes and why

  1. Why must a load-shifting measure (e.g. off-peak heat-recovery storage) be run twice in MEASUR, at two different electricity rates?

    • Because MEASUR cannot compute annual totals in one pass
    • Because Vietnam's off-peak-to-peak spread is 2.86× — the rate used changes whether the measure wins
    • To double-check for data-entry mistakes
    • Because MEASUR only accepts off-peak rates

    The card's explicit instruction: the 2.86× spread will change which measure wins, so run the case at both $0.04533/kWh and $0.12945/kWh. This foreshadows the breakeven-COP table of lesson 0007.

  2. What does the Steam System Modeler fundamentally compute?

    • The optimal heat-pump COP for each hour of the year
    • An energy/mass balance of the header system — boiler duty, losses, and the cost impact of each steam-side measure
    • A year-long 8760-hour optimization like REopt
    • The refrigerant choice for a proposed heat pump

    It balances generation, distribution, and end-use enthalpy flows and prices losses. Optimization across technologies and tariffs is REopt's job — different tool, different question.

  3. You find the US grid emission factor left in place (0.40× lower than Vietnam's). What is the practical damage?

    • None — factors are cosmetic labels in reports
    • Boiler efficiency readings become wrong
    • Every electrification measure looks ~40% better on CO₂ abatement than it really is
    • Steam pressures get mis-scaled by 40%

    Abatement = grid factor minus measure emissions, times energy switched. A grid factor 40% low inflates claimed abatement on every electric option — exactly why the card says never leave it in place.

  4. Coal is not in MEASUR's fuel list. What is the correct move?

    • Pick the closest solid fuel, override BOTH price and emission factor to the card's values
    • Choose natural gas and accept the default emission factor
    • Leave the default fuel — MEASUR auto-detects coal from pressure
    • Skip the fuel fields entirely; results are unaffected

    Same workaround as REopt's (no native coal type): substitute the nearest fuel class but override both economics and emissions. Overriding only the price leaves the emissions quietly wrong.

  5. What feeds forward from this lesson into REopt (lesson 0006)?

    • The MEASUR installer file
    • Nothing — the two tools share no data
    • The post-optimization thermal load profile — the reduced ProcessHeatLoad
    • MEASUR's internal settings database, copied into vn_context.json

    activeContext.md: "MEASUR's post-optimization thermal load profile is REopt's ProcessHeatLoad input." Sizing against the unoptimized load buys ~30% too much equipment.

  6. A colleague opens MEASUR on a fresh Windows user account to repeat your run. What happens?

    • Settings sync automatically from the cloud
    • All localization must be re-entered by hand from the VN settings card — MEASUR stores settings locally per installation/user
    • MEASUR refuses to start without a license server
    • Defaults are fine — no re-entry needed since units are global

    No CLI, no scriptable settings, local per-user database: the card is the re-entry source of truth every time. That is also why this course documents the exact values rather than assuming persistence.

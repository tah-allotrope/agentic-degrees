0011 · Capstone: Heat Pump + Thermal Storage Sizing

gap-ee week 2, days 11-14 · the gate · run log + result analysis · mission

The capstone extends the practice-copy baseline with an ASHPWaterHeater (COP 3.11) and a HotThermalStorage, runs REopt, and compares against both the Phase-3 baseline and lesson 0007's breakeven table. The honest headline: the physics and dispatch findings reproduce; the least-cost win does not at default cost assumptions — and that distinction is exactly what defensible analysis looks like.

Mission link. Success here was never "heat pump wins." It was: independently reproduce and extend a real finding, including the schema discovery, the debugging, and the negative result — all inside an isolated practice copy, with ee-heat untouched.

1. Schema discovery before any JSON (ASM-002)

Julia reflection on REopt v0.61.0 produced surprises no local documentation mentioned:

  • HotThermalStorage is a real struct — 28 fields via fieldnames(); at JSON level only max_gal > 0 is needed to activate it (confirmed against upstream's own test scenario). Defaults: 180/160°F water temps, $1.90/gal, can_serve_process_heat=false.
  • ASHPWaterHeater is a constructor function, not a struct — fieldnames() fails. Its JSON keys come from constructor kwargs: sizes in tons thermal, costs $2,250/ton + $40/ton-yr defaults, and crucially no scalar "cop" — COP interpolates a piecewise curve (heating_cop_reference vs heating_reference_temps_degF) against hourly ambient temperature.
  • REopt wires ASHPWaterHeater to the DomesticHotWaterLoad series only (scenario.jl), so the dye-house band must be declared as a DHW-quality load: we split 12,000 of the 60,000 MMBtu/yr (the plausible ≤95°C share) into DomesticHotWaterLoad, leaving ProcessHeatLoad untouched.

All fields, types, defaults, and rationale are recorded in capstone/reopt-practice/schema-notes.md — written before any scenario JSON.

5. Reading the negative NPV honestly (RISK-04-02)

Energy economics favor the heat pump on the split-out load (~$63k/yr electricity vs ~$85k/yr coal fuel displaced), but capital ($292k HP + $38k TES) over 20 years at a 10% discount swamps it: NPV −$388k. CO2 rises versus the old 13,740 baseline only because this scenario adds a new load whose electricity carries Vietnam's grid factor — against its own like-for-like BAU, emissions fall by 606 t/yr.

What would flip it: cheaper capital (real vendor quotes vs the generic $2,250/ton default), a larger verified ≤95°C load share (more sales from one machine), or off-peak-weighted operation with bigger storage at lower unit cost. Those are supplier-data questions already tracked in vn_context.json — which is why the honest verdict is "capability confirmed, investment case open," not failure.

Practice quiz

  1. Why did REopt attempt a PVWatts API call in this scenario?

    • Because a PV key was present in the scenario
    • The ASHPWaterHeater needs hourly ambient temperature; when Site.outdoor_air_temperature_degF is missing REopt synthesizes it via PVWatts
    • Because HotThermalStorage requires weather data by definition
    • Because EVN tariffs are fetched from NLR servers

    The COP curve interpolates against ambient temperature hour by hour. Supplying the real TMYx HCMC series removed the dependency — offline-safe and site-faithful.

  2. Why declare the dye-house load as DomesticHotWaterLoad rather than growing ProcessHeatLoad?

    • DHW loads are computationally cheaper to model
    • Source reading shows ASHPWaterHeater is wired exclusively to the DHW load series — a ProcessHeatLoad would never see the heat pump
    • REopt forbids two thermal loads in one scenario
    • To avoid the coal-as-natural_gas workaround

    scenario.jl assigns d["ASHPWaterHeater"]["heating_load"] = dhw_load.loads_kw. Schema discovery before writing JSON catches exactly this — guessing would have built a heat pump serving nothing.

  3. How was the corroborated COP 3.11 encoded into ASHPWaterHeater?

    • As a flat reference curve — heating_cop_reference [3.11] at a reference temperature HCMC never drops below
    • A scalar "cop": 3.11 field on the ASHPWaterHeater block
    • By editing ashp_defaults.json inside the Julia package depot
    • Via the ElectricHeater cop field set to 3.11

    No scalar cop input exists; interpolation against ambient returns 3.11 every hour because HCMC stays far above the single 50°F reference point. No package files were modified.

  4. What did the optimizer do with HotThermalStorage?

    • Declined to build it — storage is never economic without PV
    • Built it at the 20,000-gal bound (≈3.26 MMBtu-th), charging only off-peak/normal hours and discharging across the evening peak
    • Built it but dispatched only on Sundays
    • Used it to serve the 10 bar(g) steam process load directly

    767 MMBtu charged in cheap hours; 237 MMBtu discharged through the peak window plus 520 in normal hours — the exact charge-off-peak/ride-through-peak pattern activeContext.md predicted.

  5. CO2 optimal (14,300 t) exceeds the Phase-3 baseline (13,740 t). Is the design therefore a regression?

    • Yes — any emissions increase invalidates the design
    • No — the capstone adds a new 12,000 MMBtu/yr load; against its own like-for-like BAU (14,906 t) emissions fall 606 t/yr
    • Yes — REopt minimizes cost, so emissions cannot differ between cases
    • No — REopt reports CO2 excluding boiler fuel by default

    Comparisons must hold the load constant. The heat pump's grid electricity carries Vietnam's high grid factor but displaces coal steam — net −606 t/yr versus doing nothing new.

  6. NPV came out −$388k at default costs. What is the defensible conclusion?

    • Heat pumps are uneconomic in Vietnam — close the workstream
    • Adjust the discount rate until NPV turns positive
    • Physics and dispatch confirmed (COP 3.11 end-to-end; TES rides the peak); the investment case stays open on supplier data — capital quotes, true ≤95°C load share, tariff exposure
    • Delete the HotThermalStorage block and rerun until NPV is positive

    The plan's RISK-04-02 anticipated exactly this: a documented negative result is a valid capstone outcome. Never tune inputs post-hoc to force a narrative — record the sensitivities and name the data that would settle them.

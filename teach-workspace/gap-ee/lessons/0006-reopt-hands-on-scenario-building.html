2. The coal-as-natural_gas workaround (memorize this)

REopt has no native coal fuel type — choices are natural gas, propane, diesel, landfill gas. Coal is modelled as natural_gas with BOTH overrides:

  • fuel_cost_per_mmbtu: 5.30 (import-parity Indonesian sub-bituminous)
  • emissions_factor_lb_CO2_per_mmbtu: 214.2 (EPA sub-bituminous)

Missing the second override leaves REopt's natural-gas default (117.03 lb/MMBtu) in place and understates coal emissions by ~45% — every abatement claim quietly wrong. This workaround is already correctly applied in the practice copy; leave it exactly as is.

3. Why the calendar is 2017

REopt's built-in load profiles are 2017 calendar profiles. TARIFF_YEAR stays 2017 so the Mon–Sat peak window lands on the right weekdays. Change the year without changing the load-profile source and Saturday evenings silently stop peaking — the same class of error that makes SAM's weekday/weekend model understate Vietnam bills by 4.2% (tools/README.md cross-check section).

4. Reading the output like an analyst

  • Two solves — REopt runs BAU (do-nothing) and optimal passes; compare lifecycle costs between them, not to zero.
  • Boiler fuel 60,000 MMBtu/yr optimal — wait, the load is 60,000 MMBtu useful… check: with η=0.75 the fuel should be 80,000. Read the key: annual_fuel_consumption_mmbtu reports what the boiler produced toward the load; REopt's ProcessHeatLoad is defined as delivered-heat demand the boiler serves directly, so the efficiency enters through fuel-cost arithmetic rather than a 4/3 multiplier on this line. The number to trust for reproduction is emissions: 5,829 t from burning at the stated EF matches 60,000 MMBtu × 214.2 lb ÷ 2204.6 ≈ 5,829 t exactly.
  • results_garment_factory_process_heat.json — full dictionary dump next to the scenario. In Phase 4 the capstone compares its own results file against this one.

Practice quiz

  1. Why does the scenario declare the coal boiler as "fuel_type": "natural_gas"?

    • Because REopt converts gas boilers to coal automatically
    • REopt has no native coal fuel type — natural_gas stands in, with both cost AND emissions overridden to coal values
    • Because Vietnamese boilers burn gas in winter
    • It is a typo preserved for backward compatibility

    Fuel types are restricted to gas/propane/diesel/landfill-gas. The override of both fields is what makes the stand-in honest — missing the EF override understates coal by ~45%.

  2. Which reference-name key does ProcessHeatLoad require?

    • industrial_reference_name
    • doe_reference_name
    • process_reference_name
    • load_profile_name

    ElectricLoad → doe_reference_name; ProcessHeatLoad → industrial_reference_name. Both accept FlatLoad_* values, so the wrong-key mistake fails with silent NaN results rather than a clear error — trap #5 in tools/README.md.

  3. renewable_energy_fraction_series set to the scalar 0.45 causes…

    • Nothing — the signature accepts Real or Array
    • A runtime failure: "Unable to convert renewable_energy_fraction_series" — supply [0.45] × 8760 instead
    • Automatic resampling to hourly values
    • A Cambium API call that succeeds after minutes

    Despite Union{Real,Array} in the signature, scalars fail at runtime. Omitting it entirely is worse — REopt stalls on a failing Cambium API call before zeroing it. Always an 8760-length array.

  4. What did the baseline run conclude about the COP-1.0 ElectricHeater?

    • Size 0.0 MMBtu/hr, NPV $0 — resistance heat loses to coal steam at every hour
    • Built at 12.5 MMBtu/hr for peak shaving
    • Built only during off-peak hours
    • The scenario failed to solve because of it

    COP 1.0 means each kWh buys exactly one kWh of heat — more expensive than coal steam even off-peak ($4.27 would be COP-3.11 territory; resistance is ~$8+/MMBtu equivalent). REopt declining to build it is the correct answer, not a failure.

  5. Why must TARIFF_YEAR stay 2017 in make_vn_scenario.py?

    • Because EVN rates were set in 2017
    • REopt's built-in load profiles are 2017 calendars — matching years keeps Mon–Sat peak windows on the right weekdays
    • Julia cannot parse later years
    • Because 2017 was a leap year

    The generator builds the tariff vector for 2017 so that weekdays align with the 2017 load profiles. Mismatched calendars silently shift which Saturdays peak — the exact class of error the PySAM cross-check quantified at −4.2%.

  6. Your baseline prints 13,740.1 t/yr instead of exactly 13,740. This is…

    • A failed reproduction — rerun until it prints 13,740.0
    • Proof the copied files drifted from ee-heat
    • Expected rounding tolerance (±1.0) — the reproduction is valid
    • An error carried by the EASIUR warnings

    The plan's test spec allows ±1.0 t for rounding. 13,740.1 reproduces the published 5,829 + 7,911 split within display precision — checkpoint passed.

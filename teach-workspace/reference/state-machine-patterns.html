State-Machine Patterns

The card you will re-read all window · companion to 0003 state machines · Runnable code: teach-workspace/work/6.01SC/lib/sm.py · print-friendly

1 · The contract

Every machine implements two things and inherits transduce:

class SM:
    def start_state(self): ...                       # initial state
    def get_next_values(self, state, inp): ...       # -> (next_state, output)
    def transduce(self, inputs):                     # run a whole input list
        state = self.start_state()
        outs = []
        for inp in inputs:
            state, out = self.get_next_values(state, inp)
            outs.append(out)
        return outs

Naming note. The 6.01 notes call these startState and getNextValues (with a step method); this workspace's lib/sm.py uses start_state / get_next_values / transduce. Same idea, one name set.

2 · Building blocks

class Delay(SM):              # emit previous input; initial value first
    def __init__(self, initial): self._initial = initial
    def start_state(self): return self._initial
    def get_next_values(self, state, inp): return (inp, state)

class Accumulator(SM):        # running sum
    def __init__(self, initial=0.0): self._initial = initial
    def start_state(self): return self._initial
    def get_next_values(self, state, inp):
        total = state + inp
        return (total, total)

3 · Composition operators

Cascade(m1, m2)   # m1's output feeds m2's input
Parallel(m1, m2)  # same input to both; output is the pair
Feedback(m)       # m's output loops back to m's own input

Check it: Cascade(Delay(0), Accumulator(0)).transduce([1, 2, 3]) → [0, 1, 3] — the delay emits 0 first, so the running sum lags one step. This delay-and-accumulate pair is the skeleton of every filter you will meet later.

4 · Worked example: two-state controller

class BatteryController(SM):
    def start_state(self):
        return "idle"

    def get_next_values(self, state, inp):
        # inp: {"soC": 0-100, "dispatch": "charge"|"discharge"|None}
        if state == "idle" and inp["dispatch"] == "charge":
            return ("charging", "absorb")
        if state == "charging" and inp["soC"] >= 90:
            return ("idle", "standby")
        if state == "idle" and inp["dispatch"] == "discharge":
            return ("discharging", "inject")
        if state == "discharging" and inp["soC"] <= 15:
            return ("idle", "standby")
        return (state, "noop")

Rule of thumb: state is the memory. If two identical inputs must produce different outputs, the difference must live in the state.

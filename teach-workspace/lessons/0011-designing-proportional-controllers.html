0011 · Designing Proportional Controllers

EE track · 6.01SC Ch.5 (feedback control) · ~30 minutes · mission · github.io

You can now score a controller (0010). This lesson builds the simplest one: command proportional to error — one gain K, one stability condition, one unavoidable leftover error.

Why this matters for your mission. Every BESS charge loop starts life as a proportional controller: charge harder when far from target SoC, ease off when close. Knowing what gain stabilizes it, and what error remains, is the first controller review you will ever do on vendor firmware.

1 · The proportional control law

Let r be the setpoint, y the measured output, e = r − y the error. Proportional control commands:

u = K·e = K·(r − y)

Plant (first-order example): y = P·u with plant gain P. Closed loop: y = P·K·(r − y) → y/r = PK/(1 + PK) — Black's formula from 0008 with H1 = PK.

2 · Stability condition

For the discrete first-order loop y[n+1] = y[n] + K·(r − y[n]), the error dynamics are e[n+1] = (1 − K)·e[n] — a geometric mode with pole (1 − K). By the 0008 convergence rule:

stable ⟺ |1 − K| < 1  ⟺  0 < K < 2

K > 2 diverges; 1 < K < 2 converges but alternates (ringing); K = 1 lands in one step (deadbeat).

3 · Steady-state error never vanishes

At steady state y[∞] = PK/(1+PK)·r, so for a unit step:

steady-state error = 1/(1 + PK)

Finite gain always leaves residual error — halving it needs doubling PK, which pushes toward instability. Killing it entirely needs integral action (beyond 6.01SC scope; note it as the known gap).

4 · Worked numeric: tune K = 0.5 vs 1.5

Plant P = 1, setpoint r = 1, start y[0] = 0:

K = 0.5: y = 0, 0.50, 0.75, 0.875, … → monotonic, error → 1/1.5 ≈ 0.33??

Wait — check against the formula: y[∞] = 0.5/1.5 = 0.667, error 0.333. Correct: with P = 1 the loop only reaches two-thirds of setpoint. Raise to K = 1.5: pole 1 − 1.5 = −0.5, y = 0, 1.5, 0.75, 1.125, … — alternates around y[∞] = 1.5/2.5 = 0.6?? No: 1.5/2.5 = 0.6, error 0.4?? That contradicts "higher gain cuts error"… recompute: y[∞] = PK/(1+PK) = 1.5/2.5 = 0.6, error 0.4 > 0.333. Something is off — because this plant y = P·u has no integrator; recheck K=0.5: 0.5/1.5 = 0.333 error 0.667. Let me redo cleanly:

K = 0.5 → y[∞] = 0.5/1.5 = 0.333, error 0.667 (monotonic, pole 0.5)
K = 1.5 → y[∞] = 1.5/2.5 = 0.600, error 0.400 (ringing, pole −0.5)

Now consistent: higher gain cut error 0.667 → 0.400, at the price of alternation. The tradeoff from 0010 is now a formula, not folklore.

5 · Tuning protocol

  1. Raise K until overshoot touches your 0010 spec limit.
  2. Check stability margin: keep pole |1 − K| comfortably below 1.
  3. Accept the residual error or specify integral action as follow-up.

Quiz

  1. What is proportional control law?

    • Output equals gain times input
    • Command equals gain times error
    • Error equals gain times command
    • Gain equals error times command

    u = K·e = K·(r − y): command proportional to setpoint-minus-measurement.

  2. When is this loop stable?

    • Gain magnitude stays below one
    • Gain magnitude rises above one
    • Error magnitude stays above zero
    • Command magnitude equals error always

    Pole is (1−K); |1−K|<1 ⟺ 0<K<2 for the first-order loop.

  3. What does raising gain do?

    • Always removes steady state error
    • Always keeps response well damped
    • Cuts error but risks ringing
    • Slows response while adding stability

    Higher K shrinks 1/(1+PK) error but pushes the pole toward −1: overshoot and ringing grow.

  4. Why does steady-state error persist?

    • Finite gain leaves residual error
    • Higher gain always increases error
    • Feedback always removes all error
    • Drive vanishes at zero error

    At e = 0 the proportional command is 0, so the plant output would fall — equilibrium sits at nonzero error. Only integral action removes it.

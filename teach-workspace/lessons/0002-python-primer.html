0002 · Python Primer: names, functions, collections, loops

6.0001-primer (DEC-015) · ~20 minutes · for the rusty, not the new

Everything in this lesson exists so that 6.01SC Chapter 4 (state machines) and 6.0002 (computational thinking) make sense. You are not learning Python as a goal — you are learning the dialect those two courses think in.

1 · Names bind to objects

Python has no variables-as-boxes; it has names bound to objects. x = 5 binds the name x to the object 5. Rebinding just points the name elsewhere. This matters in 6.01SC because every programming exercise there is about tracking which name points at what.

x = 5
x = "hi"     # same name, different object — fine, no type declaration
y = x        # y and x now name the SAME string object

2 · Functions own their scope

A function body is a private room: names bound inside it are invisible outside, and return is the only way out with a value. 6.01SC's state-machine code leans on this hard — each machine method gets its own clean scope.

def square(n):     # n is a parameter — local
    return n * n   # hands the value back

print(square(4))   # 16
print(n)           # NameError — n does not exist out here

3 · Three collections do 90% of the work

lst = [1, 2, 3]        # list  — MUTABLE: append, assign by index
tup = (1, 2, 3)        # tuple — IMMUTABLE: a frozen record
d = {"a": 1, "b": 2}   # dict  — key → value lookup

Mental hook: a list is a to-do list (you can rewrite it), a tuple is a receipt (fixed), a dict is a phone book (look up by name). For BESS work: a battery state log is a list of records; each record is a tuple; the inverter's settings table is a dict keyed by parameter name.

4 · Loops and comprehensions

for i in range(2, 5):     # 2, 3, 4 — stop is EXCLUSIVE
    print(i)

[x * 2 for x in range(3)]          # → [0, 2, 4]  (list comprehension)
{k: len(k) for k in ["a", "bb"]}   # → {"a": 1, "bb": 2}

A comprehension is just a loop that builds a collection in one expression — you read it "for each x in ..., put f(x) in".

5 · Recall check (write before you click)

  1. Predict: [i ** 2 for i in range(4)].
  2. Predict: what does d["c"] = 3 do when d already has "a" and "b"?
  3. Fix the bug: total = 0; for i in range(1, 5): total = total + i; print(total) — what prints?

Answers: (1) [0, 1, 4, 9]; (2) adds a third entry "c": 3; (3) 10 (1+2+3+4). If you got all three, the primer worked — go take the diagnostic again for a clean 8/8.

Quiz

Which statement about Python names is true?
Assignment binds a name in a namespace; the object lives its own life and the name can be rebound at any time.
What is the result of this expression?
[i ** 2 for i in range(4)]
range(4) yields 0, 1, 2, 3; squaring gives 0, 1, 4, 9.

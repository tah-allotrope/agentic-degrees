0003 · 6.01SC Unit 1 — State Machines

EE track · 6.01SC Ch.4 · ~25 minutes

A state machine is the cleanest way to model anything that remembers: a battery controller, a grid relay, a vending machine, a search algorithm. You are about to meet the single most reused abstraction in this whole curriculum — and in the power-electronics work it leads to.

Why this matters for your mission. A BESS inverter controller is a state machine: idle → charging → discharging → idle, with transitions fired by signals like SoC thresholds, grid frequency, or dispatch commands. When you later read 6.622 power-electronics control schemes, "the controller is in state X" is exactly the language they speak.

1 · What a state machine is

Formally, a state machine has:

  • States S — everything the system remembers about its past.
  • Inputs I — what the world offers at each step.
  • Outputs O — what the machine emits.
  • Transition function f: (state, input) → next state.
  • Output function g: (state, input) → output.
  • startState — where it begins.

The one-sentence version: a machine whose next action depends on its history, summarized by a state.

2 · The Python pattern (memorize the skeleton)

class SM:
    startState = None

    def getNextValues(self, state, inp):
        nextState = state            # override in subclasses
        return (nextState, inp)      # default output: the input itself

    def start(self):
        self.state = self.startState

    def step(self, inp):
        (s, o) = self.getNextValues(self.state, inp)
        self.state = s
        return o

You write startState and getNextValues; the base class handles stepping. The whole 6.01SC course is built on extending this class.

3 · Worked example: a battery controller

class BatteryController(SM):
    startState = "idle"

    def getNextValues(self, state, inp):
        # inp is a dict: {"soC": 0-100, "dispatch": "charge"|"discharge"|None}
        if state == "idle" and inp["dispatch"] == "charge":
            return ("charging", "absorb")
        if state == "charging" and inp["soC"] >= 90:
            return ("idle", "standby")
        if state == "idle" and inp["dispatch"] == "discharge":
            return ("discharging", "inject")
        if state == "discharging" and inp["soC"] <= 15:
            return ("idle", "standby")
        return (state, "noop")       # hold state, output nothing

Trace it: start idle; dispatch=charge → charging (output absorb); SoC hits 90 → back to idle (standby). The state variable is the machine's memory — without it, the controller cannot know whether it is mid-charge or idle.

4 · Why this abstraction carries the whole course

  • Unit 2 (signals & systems): LTI systems are state machines with infinite states.
  • Unit 3 (circuits): digital circuits are state machines whose states are flip-flop values.
  • Unit 4 (planning): search explores the state space of the world model.

Quiz

What does the state of a machine summarize?
State is the compressed memory: enough about the past that, given the next input, the future is fully determined.
Which method computes the next state and output?
getNextValues(state, inp) returns the (nextState, output) pair — the heart of the machine. step() drives it and updates the state.
In the battery example, why does the controller need state?
The same input (e.g. SoC = 50%) demands different action depending on whether the controller is idle or charging — only remembered state distinguishes them.
What does step() do after each input arrives?
step() calls getNextValues, stores the returned next state, and returns the output — the machine's state advances one step.

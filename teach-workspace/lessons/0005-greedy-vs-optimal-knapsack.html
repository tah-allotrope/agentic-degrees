0005 · Greedy vs. Optimal Knapsack

SE track · 6.0002 Lec.1 · ~25 minutes · mission

Many engineering choices are knapsacks: a battery must fit a weight and cost budget, a grid battery must fit a footprint and a budget, a shipping route must fit a time window. The knapsack problem is the cleanest place to learn the trade-off that runs through all of 6.0002 — fast heuristic vs. exact but expensive search.

Why this matters for your mission. Sizing a BESS ("how many MWh fit in this budget to capture the most revenue?") is a knapsack with a dollars constraint and a revenue objective. You will need the language of this lesson to argue why a spreadsheet's greedy pick may not be the best pick — and when the exact answer is worth the exponential cost.

1 · What an optimization problem is

Every optimization problem has two ingredients:

  • An objective function to maximize or minimize (revenue, trip time, value).
  • A set of constraints (a budget, a weight limit, a deadline).

The knapsack version: given items with value and cost (here: calories), pick a subset within a cost limit that maximizes total value.

2 · Greedy: pick the "best" next item

def greedy(items, maxCost, keyFunction):
    itemsCopy = sorted(items, key=keyFunction, reverse=True)
    result = []
    totalValue, totalCost = 0.0, 0.0
    for item in itemsCopy:
        if totalCost + item.getCost() <= maxCost:
            result.append(item)
            totalCost += item.getCost()
            totalValue += item.getValue()
    return (result, totalValue)

The whole algorithm is sort by a key, then take whatever fits. The choice of key changes the answer. With a 1000-calorie limit and the lecture's menu, the shipped code reports:

  • Greedy by value → total 424.0 (burger, pizza, beer, wine, apple).
  • Greedy by cost → total 413.0.
  • Greedy by density (value/cost) → total 413.0.

Same items, same limit, three different totals. Greedy-by-value wins on this menu, but that is coincidence.

3 · Why greedy can miss the optimum

Greedy commits: once it takes an item, it never changes its mind. A clean counterexample — capacity 10, one item worth 100 at cost 9, two items worth 60 at cost 5 each:

  • Greedy by value takes the 100 (9 used, 1 left) → total 100.
  • Optimum is both 60s → total 120.

Greedy is fast (O(n log n) from the sort) and usually good, but never guaranteed optimal.

4 · Optimal: exhaustive enumeration

The only guarantee is to consider every subset: generate all 2^n combinations, keep those within the limit, return the best value. That is exponential, so it only works for small n — which is exactly why PS1 (cow transport) asks you to write both and compare: greedy runs instantly, brute force is exact but explodes.

The lesson to internalize: "greedy" and "optimal" are different words. A greedy answer is a claim about effort; an optimal answer is a claim about correctness. Say which one you produced.

Quiz

  1. What does an optimization problem consist of?

    • Objective plus constraints
    • Inputs plus outputs
    • Loops plus variables
    • Classes plus methods

    An objective function to optimize and a set of constraints the solution must honor — nothing more.

  2. Greedy by value selects items in what order?

    • Highest value first
    • Lowest cost first
    • Random order first
    • Alphabetical order first

    It sorts items descending by the key function, then walks the sorted list taking everything that fits.

  3. Why can greedy miss the optimum?

    • It never backtracks
    • It always backtracks
    • It picks randomly
    • It sorts descending

    Greedy commits to each item as it goes and never revisits a decision, so it can fill the bag in a way that locks out a better combination.

  4. What guarantees the optimal knapsack?

    • Exhaustive enumeration
    • Greedy selection
    • Sorting items
    • Random sampling

    Only considering every subset guarantees the optimum; it is exact but exponential in the number of items.

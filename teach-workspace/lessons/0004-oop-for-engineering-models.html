0004 · Object-Oriented Models for Engineering

EE track · 6.01SC Ch.3 §3.8 · ~25 minutes · mission

Objects let you attach the data of a system to the operations that act on it, so a battery cell, an inverter, or a grid feeder becomes a thing you can hand around and reuse instead of a tangle of parallel lists. This is the modeling half of the state-machine lesson: the state machine says how a controller behaves, the object model says how you represent the thing being controlled.

Why this matters for your mission. A battery-energy-storage sizing tool is an object model: a Cell knows its chemistry, capacity, and internal resistance and answers "how much energy is left at this current"; a BatteryPack composes cells; a Feeder aggregates loads. When you later read 6.061 / 6.622 code or vendor datasheet tools, "the Cell object exposes get_state_of_charge()" is the normal way these systems are described.

1 · The idea: data plus the procedures that use it

Plain data (dim = 6, balance = 100) and the functions that work on it (getArea, deposit) drift apart as a program grows. Object-oriented programming groups them: a class is the template, an instance is a concrete object built from it, and attributes (self.dim, self.currentBalance) hold the instance's own data. This is the "abstraction" of the PCAP framework — callers use the object without seeing its guts.

2 · The Python shape: __init__, self, methods

class Square:
    def __init__(self, initialDim):
        self.dim = initialDim

    def getArea(self):
        return self.dim * self.dim

    def setArea(self, area):
        self.dim = area ** 0.5

    def __str__(self):
        return "Square of dim " + str(self.dim)

s = Square(6)
s.getArea()        # 36
Square.getArea(s)  # 36 — s is just the first argument
s.setArea(100)
s.dim              # 10.0
print(s)           # "Square of dim 10.0"

Notes that save debugging time:

  • __init__ runs at construction and sets up the instance's state.
  • Every method takes self first — the instance it operates on. Forgetting it gives the "add is not defined" error from Ch.2.
  • __str__ makes the object print nicely; it is the debugging aid.

3 · Inheritance: override the parts that differ

When two account types share everything but one rule, don't copy the class — inherit and override. PremierAccount(Account) means "exactly like Account but with these additions/overrides".

class Account:
    def __init__(self, initialBalance):
        self.currentBalance = initialBalance
    def balance(self):
        return self.currentBalance
    def deposit(self, amount):
        self.currentBalance = self.currentBalance + amount
    def creditLimit(self):
        return min(self.currentBalance * 0.5, 10000000)

class PremierAccount(Account):
    def creditLimit(self):
        return min(self.currentBalance * 1.5, 10000000)

b = PremierAccount(1000)
b.creditLimit()  # 1500.0
b.deposit(500)   # inherited — works without redefinition
b.balance()      # 1500.0

Because every instance knows its own class, creditLimit() dispatches to the right implementation without an if anywhere — polymorphism. This is how a grid model can hold a mixed list of Account-like objects and ask each for its behavior.

4 · Composition: objects inside objects

Just as BinaryOp nodes nest (HW1's syntax trees), engineering objects nest: a pack contains cells, a feeder contains loads. An object whose attributes are other objects is a compositional data type — the same idea as a syntax tree, and the backbone of every sizing and simulation model you will write.

Quiz

  1. What does a class group together?

    • Data and its procedures
    • Files and their names
    • Inputs and their types
    • Loops and their counts

    A class bundles the data (attributes) with the procedures that operate on it (methods) — the object-oriented answer to modularity and abstraction.

  2. Which keyword names the instance inside a method?

    • self
    • class
    • this
    • init

    By convention the first parameter is named self; it is the instance the method is called on, and instance attributes live on it.

  3. What does s.getArea() pass as the first argument?

    • The instance s
    • The class type
    • The area value
    • The module name

    Method call sugar: s.getArea() is exactly Square.getArea(s), so self receives the instance s.

  4. What does a subclass inherit?

    • All parent methods
    • Only new methods
    • The local scope
    • The module state

    Inheritance copies everything from the parent and lets the subclass override or add specific parts — no repeated code for the shared behavior.

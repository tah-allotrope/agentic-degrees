0009 · Graph Models and Shortest Paths

SE track · 6.0002 Lec.2–3 (graphs) · ~30 minutes · mission · github.io

Not every problem is a list. When the question is "what connects to what and at what cost," the model is a graph — nodes, edges, weights — and the algorithms are the ones that walk it. This lesson builds the graph model you will reuse for routing, dependency analysis, and every "shortest/cheapest path" question in the SE track.

Why this matters for your mission. A grid is a graph: substations are nodes, feeders are edges, impedance or loss is the weight. "Cheapest way to serve this load" and "which line overloads first" are shortest-path and constrained-path questions on that graph. The same model that routes a data packet routes a megawatt — the vocabulary is identical.

1 · A graph is a set of connections

A graph G = (V, E) is a set of vertices V and edges E connecting pairs of vertices.

  • Directed vs undirected: directed edge u → v is one-way (power flow under a direction); undirected u — v is both ways (a road).
  • Weighted vs unweighted: each edge may carry a number — distance, cost, loss, time. Unweighted = weight 1.
  • Path cost: sum of edge weights along the path. The shortest path minimizes that sum.

Example — 4-node feeder (undirected, weighted by loss):

A —5— B —3— D
 \   / \
  9 2   4
   C —6— D     edge A–B 5, A–C 9, B–C 2, B–D 3, C–D 6

2 · How to represent a graph in code

Two canonical representations — both use dicts, which is why week-1 dict fluency matters:

# adjacency list (sparse-friendly, the 6.0002 default)
graph = {
    'A': [('B', 5), ('C', 9)],
    'B': [('A', 5), ('C', 2), ('D', 3)],
    'C': [('A', 9), ('B', 2), ('D', 6)],
    'D': [('B', 3), ('C', 6)]
}

# adjacency matrix (dense-friendly)
# matrix[u][v] = weight or 0/inf if no edge

An adjacency list is a dict of list of pairs — exactly the {k: k*k for k in range(n)} shape from 0006, plus a loop over neighbors. Prefer lists for sparse grids (most node pairs not directly connected); matrices for dense ones.

3 · BFS: shortest path when every edge costs 1

Breadth-first search expands in waves: all distance-1 nodes, then all distance-2 nodes, …

from collections import deque

def bfs_shortest(graph, start, goal):
    queue = deque([(start, [start])])
    visited = {start}
    while queue:
        node, path = queue.popleft()
        if node == goal:
            return path
        for nbr, _ in graph[node]:
            if nbr not in visited:
                visited.add(nbr)
                queue.append((nbr, path + [nbr]))
    return None

BFS is O(V + E) and guarantees the fewest edges — but only when every edge has equal cost. With weights, the fewest edges can be the most expensive path (A→C is one edge cost 9, but A→B→C is two edges cost 7).

4 · Weighted shortest path: Dijkstra's idea

When edges have different weights, BFS fails. Dijkstra's algorithm keeps the best-known cost to each node and repeatedly relaxes edges — "can I reach v cheaper through u?"

dist = {v: inf for v in graph}; dist[start] = 0
unvisited = set(graph)
while unvisited:
    u = min(unvisited, key=lambda x: dist[x])   # closest unvisited
    unvisited.remove(u)
    for v, w in graph[u]:
        if dist[u] + w < dist[v]:               # relaxation
            dist[v] = dist[u] + w

Key properties: Dijkstra requires non-negative weights, runs O((V+E) log V) with a heap, and the dist dict is the answer — the standard pattern in PS1's transport problem and in every later graph problem set.

5 · Worked numeric walk (the feeder above)

Shortest path A → D:

  • A→D direct: no edge.
  • A→B→D: 5 + 3 = 8
  • A→C→D: 9 + 6 = 15
  • A→B→C→D: 5 + 2 + 6 = 13
  • A→C→B→D: 9 + 2 + 3 = 14

Cheapest is A→B→D cost 8 — BFS would have returned A→C→D or A→B→D with equal hops (both 2 edges) and could pick the cost-15 path; Dijkstra finds the cost-8 path because it tracks cost, not hops.

Quiz

  1. What does a weighted graph add to an unweighted graph?

    • A number on each edge
    • A number on each node
    • A direction on each edge
    • A color on each node

    Weighted = every edge carries a cost (distance, loss, time); the path cost is the sum of its edge weights.

  2. Which structure is the natural adjacency-list representation in Python?

    • Dict mapping node to neighbor list
    • List mapping index to weight
    • Set mapping edge to node
    • Tuple mapping cost to path

    Adjacency list is {node: [(neighbor, weight), …]} — a dict of lists, the direct use of week-1 dict skills.

  3. BFS guarantees the shortest path only when what holds?

    • Every edge has equal cost
    • Every node has equal degree
    • Every path has equal length
    • Every graph has equal weight

    BFS minimizes hop count. With equal weight, hops = cost; with varying weights, fewest hops can be most expensive.

  4. What is the relaxation step in Dijkstra's algorithm?

    • Update dist[v] if via u is cheaper
    • Update dist[u] if via v is longer
    • Remove v from the graph entirely
    • Add u to the visited path

    Relaxation: if dist[u]+w(u,v) < dist[v], set dist[v] to the cheaper value — the core loop that propagates best costs.

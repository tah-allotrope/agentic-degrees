0014 · Graph Optimization Problems

SE track · 6.0002 Lec.3 (graphs) · ~30 minutes · mission · github.io

Shortest path assumed any route is allowed. Real problems add constraints — a budget, a capacity, a must-visit list — and the unconstrained optimum stops being feasible. This is where greedy breaks and brute force earns its keep.

Why this matters for your mission. "Cheapest feeder upgrade under a capex cap that keeps every load served" is a constrained graph problem: minimize loss subject to budget. The knapsack tradeoff from 0005 returns wearing a graph costume — greedy vs optimal, now on networks.

1 · Constraints change the answer

Example: each edge has a cost (loss) and a build price; total price must stay under budget B. The cheapest-loss path may blow the budget, so the feasible optimum is a different path — Dijkstra alone cannot see the budget.

A–B: loss 3, price 8 | A–C: loss 5, price 2 | B–D: loss 3, price 8
C–D: loss 5, price 2 | B–C: loss 1, price 1 ;  budget B = 6

2 · Greedy fails: a concrete trap

Greedy by loss picks A–B (loss 3, price 8) — already over budget B = 6, dead end. Feasible paths: A–C–D (loss 10, price 4 ✓), A–C–B–D (loss 5+1+3 = 9, price 2+1+8 = 11 ✗), A–B–C–D (price 8+1+2 = 11 ✗). Greedy's first step killed every feasible completion; the optimum is A–C–D at loss 10.

3 · Brute force: enumerate and filter

List all simple paths, drop infeasible ones, keep the min-loss survivor:

def best_feasible(graph, start, goal, budget):
    best, best_loss = None, float('inf')
    for path in all_simple_paths(graph, start, goal):
        if price(path) <= budget and loss(path) < best_loss:
            best, best_loss = path, loss(path)
    return best, best_loss

Guarantees optimality at exponential cost — the baseline every smarter method must beat (same moral as 0005's brute-force knapsack).

4 · Dynamic programming: memoize the subproblem

When the constraint is a small integer budget, memoize on (node, money_spent): best loss from node to goal with that spend. Each state solves once — overlapping subproblems collapse the search the way DP beat re-computation in the knapsack follow-up. State count = V × B: pseudo-polynomial, practical for small B.

5 · Worked answer for the example

Enumerate A → D simple paths (prices): A–B–D (16 ✗), A–C–D (4 ✓ loss 10), A–B–C–D (11 ✗), A–C–B–D (11 ✗). Only A–C–D feasible → optimum loss 10. Unconstrained Dijkstra would answer A–B–D loss 6 — infeasible under the cap, and wrong for the real question.

Quiz

  1. What constrains this graph problem?

    • Edges have uniform unit cost
    • Limits on cost or visits
    • Graphs contain too many nodes
    • Paths must revisit every node

    A budget/capacity/must-visit constraint makes the unconstrained optimum infeasible.

  2. Why can greedy fail here?

    • It explores every possible path
    • It guarantees the optimal answer
    • It never picks any edge
    • Local picks violate global budget

    A locally cheapest first step can overspend the budget and kill all feasible completions.

  3. What does brute force guarantee?

    • Optimal answer at exponential cost
    • Fast answer with small error
    • Linear time on large graphs
    • Constant memory during full enumeration

    Enumerate all paths, filter by constraint, keep the min — optimal, exponentially slow.

  4. What does dynamic programming exploit?

    • Random sampling of path space
    • Greedy choice at each node
    • Overlapping subproblems with memoization stored
    • Uniform weights across all edges

    Memoize (node, spend) → best loss; each state solved once instead of re-enumerated.
